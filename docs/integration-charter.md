# N.E.K.O 整合宪章（Integration Charter）

> 定稿：2026-09-19 ｜ 方法：grill-me 逐分支访谈，11 项决策全部确认 ｜ 效力：后续所有整合工作的最高依据
> 配套调研：`/mnt/shared/_Projects/N.E.K.O/docs/research/README.md`（三维度横向研究）

## 一、产品定位（为什么整合）

**统一 AI 伴侣**：多角色、一套世界记忆，跨桌面/QQ/微信/终端随处可达的 AI 伴侣系统。

## 二、十一项已确认决策

| # | 决策点 | 结论 |
| --- | --- | --- |
| 1 | 核心动机 | 统一 AI 伴侣（一人格一记忆随处可达），非群聊 bot 强化、非产品化首发、非纯学习 |
| 2 | 主入口 | **桌面 / IM / 终端三入口并重**（终端 = monika 式人格寄生在 Claude Code 会话） |
| 3 | 人格体系 | **多角色可插拔**（角色卡=数据），且**角色之间可以交流** |
| 4 | 角色交流形态 | 三项全要：**同台群聊**（用户+多角色同会话互怼）+ **后台社交生活**（角色自主互动，用户可见痕迹）+ **共享世界+独立人格**（世界记忆共享、私人记忆独立） |
| 5 | 情感定位 | **角色卡自带关系模板**（有的恋爱向、有的损友向），系统只提供中性配套基础设施（affection 轴作为通用能力按卡配置） |
| 6 | 使用规模 | **自己用 + 从第一天预留多用户**（用户维度隔离设计到位，参考 N.E.K.O Steam 可分发形态） |
| 7 | 记忆同步强度 | **实时强一致**（跨入口实时可感：QQ 说完桌面当下就知道——需事件总线+活跃会话热同步） |
| 8 | LLM 成本 | **混合分层**（主力对话用 API；记忆抽取/情绪判定/后台社交/守夜用便宜或本地小模型） |
| 9 | 骨架主体 | **N.E.K.O 子项目为基底**（桌面+记忆+QQ+微信全栈最强、Steam 形态匹配分发目标），其他项目模块作为插件/服务逐步迁入 |
| 10 | 记忆栈 | **双层服务化**：A_memorix 以 Python 3.12 独立进程跑检索服务（双路+图谱扩展），N.E.K.O memory_server（3.11）保留语义层（五维/信任/证据链），HTTP 互通——「检索找 A_memorix，质量治理找 N.E.K.O」 |
| 11 | MVP 第一站 | **先跑通单角色跨端**（同一人格跨桌面/QQ/微信/终端 + 同一套中心记忆 + monika 三件套装载 + 快赢件移植）；多角色同台与后台社交放二期 |

## 三、由决策推导关闭的单向门

| 单向门 | 推导结论 |
| --- | --- |
| 进程拓扑 | 中心服务化：N.E.K.O 桌面主进程（3.11）+ A_memorix 检索服务（3.12）+ 事件总线 + 各入口客户端 |
| QQ 栈 | 用 N.E.K.O 自家连接栈（`qq_client.py` OneBot v11 双向 WS + `qq_open_plat.py` 官方开放平台），不引入 maim_message/mofox-wire |
| NapCat 生命周期 | N.E.K.O 托管模式（自带启动器/二维码搬运/重试，自己用体验优先） |
| 输出范式 | N.E.K.O XML `<msg>` 块（QQ 端）+ 桌面块模型；MaiBot 人味后处理管线在 XML 之后作为可插拔层接入 |
| 微信 | N.E.K.O wechat_integration（官方 iLink bot API）起步，个人号协议继续观望 |
| TG/海外通道 | 二期经 NagaAgent 的 vendored OpenClaw 侧车覆盖，或按需直连 |
| 记忆写入策略 | 自动抽取为主（RP 体验），保留 booku 式命令写入作为 per-角色可选策略 |

## 四、MVP 交付物定义（第一站验收标准）

1. 选定一个人格（角色卡），在**桌面 + QQ + 微信 + 终端**四个入口都能对话
2. 四个入口共享同一套中心记忆（实时强一致：任一入口说过的话，其他入口当下可提及）
3. monika 三件套（OOC 五规则/输出通道分层/昵称状态机）装载为系统级 prompt 模块
4. MaiBot 人味管线（分段器/错别字/打字延迟）作为 QQ 端可开关插件接入
5. 混合分层模型策略生效（主对话/杂活分档）

## 五、二期预告（不在 MVP 内）

多角色同台群聊、后台社交生活、共享世界记忆层（全工作区空白，需从零设计世界状态模型）、affection 通用好感轴、多用户开放。

## 六、风险登记

- **实时强一致**是最高档成本选择：事件总线 + 热同步的复杂度别低估（MVP 可先回合级，架构按实时设计）
- N.E.K.O 抽象与实现脱节（SDK adapter 面 vs 自建 QQConnectionBase）：MVP 沿用现状，二期统一到 SDK 面时再还债
- A_memorix 运行时假设 MaiBot 的 chat_manager/person_info 体系：双层服务化需要实现 port 适配
- 多角色同台是 N.E.K.O 单角色激活架构的伤筋动骨改造：二期最大技术风险
